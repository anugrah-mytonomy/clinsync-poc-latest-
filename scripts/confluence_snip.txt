-batch
  API->>Worker: enqueue ingest (server-side)

  User->>UI: Continue to Tagging
  User->>UI: Confirm and Continue
  loop until still_in_progress = 0
    UI->>API: POST .../batches/{id}/commit
  end
  UI->>API: GET /api/v1/library/documents
```

Worker progress is **not** shown on the Uploading or Tagging steps in the current UI; commit waits until the server reports nothing still in progress.

## 10. Errors, retry, and known gaps

| Scenario | Frontend behaviour |
|----------|-------------------|
| Unsupported type / empty / too large | Row rejected on drop; never uploaded |
| ZIP bad entries | **Warnings** on row; upload allowed if at least one usable entry |
| check-duplicates fails | Banner on Add Content; modal not shown |
| Part upload fails | Row failed; **Retry** on Uploading step |
| complete-batch partial failure | Per-file error in batch response; failed rows retryable |
| Duplicate refused at initiate | Failed row; message from server; typically not retryable |
| User removes item during upload | `cancel()` → best-effort `POST abort` |

**Known gaps (POC)**

- No `GET …/parts` resume after full page reload.
- No live worker status on Uploading step (`processing` / `entries_done`).
- Tag specialties / document types are UI-only until backend accepts them on commit.

## Quick reference — API calls by user action

| User action | API calls |
|-------------|-----------|
| Open Content Library | `GET /api/v1/library/documents` |
| Drop files | *(none)* |
| Click Upload | `POST /api/uploads/check-duplicates` |
| Save Selection (if modal) | *(then same as upload start)* |
| Upload start (per file, parallel) | `initiate` → `parts/presign` → S3 `PUT` |
| All parts done | `POST /api/uploads/complete-batch` |
| Confirm & Continue | `POST /api/v1/uploads/batches/{id}/commit` (repeat while `still_in_progress`) |
| Download in library | `GET /api/v1/library/documents/{id}/download` |
